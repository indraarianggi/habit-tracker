# Code Conventions

Rules for any change under `src/`, the build configs, and dependencies.

## Imports

Application code imports through the `@/` alias (`@/server/auth`, `@/components/ui/button`) — declared in `tsconfig.json` `paths` and `vite.config.ts` `resolve.alias`. Deep relative imports (`../../`) are leftovers from the pre-alias era; writing a new one is a mistake. `tsconfig` uses `paths` without `baseUrl`: `baseUrl` is deprecated in TypeScript 6, and re-adding it fails `typecheck` with TS5101.

`src/routeTree.gen.ts` is generated by the TanStack Start plugin and gitignored, while `src/router.tsx` imports it — so on a clean checkout, run `dev` or `build` once before `typecheck` can resolve. Treat it as build output: never hand-edit it, never import around it.

## Dependencies

Every `package.json` entry is exact-pinned and the lockfile is consumed `--frozen-lockfile` (README). Add with `pnpm add -E <pkg>`; a caret range on a new dependency breaks the pin convention the moment the lockfile regenerates.

## Server modules

`src/server/auth.ts` works at import time: it validates `BETTER_AUTH_URL` / `BETTER_AUTH_SECRET` / `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`, opens SQLite at `DATABASE_PATH` (WAL, foreign keys), runs the auth migration, and exports `authOptions` carrying the live `database`. Importing it requires those env vars and touches the database file; the Playwright config sets them before workers import (see `testing.md`).

Open items to respect when touching this area:

- **Migration ownership**: `user_version` is per-database, and `migrateAuth` (`src/server/auth-schema.ts`) throws above version 1. The first app-table migration (Tasks, Check-ins) must first move schema migration to a single owner — an ordered migration list in a `src/server/db.ts` — or server startup crashes on the bump. ADR-0002 already commits to migrations running at app start.
- **Production URL scheme**: `BETTER_AUTH_URL` accepts `http://` today; requiring `https://` outside localhost is an open hardening item.
- **Error states**: keep the app shell mounted when a fetch or sign-out fails — render the error inline instead of unmounting the header and its Sign out control. `src/routes/today.tsx` currently replaces the whole page on error; fix that flow when touching it.

## Runtime

The project requires Node ≥ 22.12 (pnpm itself needs `node:sqlite`). A launch that dies with `ERR_UNKNOWN_BUILTIN_MODULE: node:sqlite` resolved an older Node from PATH — invoke the node binary directly (for supervised processes: `<node>/bin/node ./node_modules/vite/bin/vite.js dev`, not bare `pnpm`).
